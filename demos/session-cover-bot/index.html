Automated session cover

Tutors report a live-session problem to a bot instead of the moderation chat. The bot walks them through the fix from the Moderation Help Center, gives one timed recovery attempt, and assigns an eligible cover tutor automatically when the session can't continue.

  1. Tutor reports the issue to the bot
  2. Bot identifies the issue type
  3. Quick fix + one timed recovery attempt
  4. Solved: session continues
  5. Not solved: cover required
  6. Eligible tutor assigned, SMS + mentor notified, case logged

      Business rules & safeguards
        
      
      • Only tutors who match the session's grade eligibility are considered.
        • 
      
      • A tutor with an overlapping session is never selected.
        • 
      
      • One cover request is reserved for one tutor at a time; no duplicate assignment.
        • 
      
      • Every bot question, answer and decision is timestamped for audit.
        • 
      
      • If the cover tutor doesn't accept or join within the timeout, the next eligible tutor is tried.
        • 
      
      • One recovery attempt per session. A second issue in the same session goes straight to cover.
        • 
      
      • Repeated issues across sessions in one day are flagged for review or proactive reassignment.
        • 
      
      • Human moderation stays as the exception path for cases the bot can't classify.
        • 
    
      
    
      Expected impact
        
      
      • Fewer moderation employees needed to run cover cases by hand.
        • 
      
      • Faster response when a tutor can't continue.
        • 
      
      • One consistent decision process instead of individual chat handling.
        • 
      
      • Less student waiting time and session disruption.
        • 
      
      • Clear data on why sessions get interrupted and where cover demand peaks.
        • 
      
      • Visibility into peak cover days, repeat tutors and staffing needs.
        •
